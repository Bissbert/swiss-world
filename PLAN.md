# Swiss World: a 1:1 Switzerland dimension 

Status: **PLAN v3, awaiting approval.** No code and no scaffold yet. The server, the pack and the running game have not been touched.

Target: NeoForge 21.1.262 · Minecraft 1.21.1 · Java 21 · a dedicated modded server (Docker).

Working names: mod id `swissworld`, dimension `swissworld:switzerland`.

Figures marked **(unverified)** are estimates to be measured in M0/M1. Figures marked **(measured)** come from the swisstopo API, queried on 2026-10-19.

### What changed in v3 (your second round of feedback)

| Topic | v2 | **v3** |
|---|---|---|
| Saving | save only player-modified chunks (mixins) | **Vanilla saving.** Generated chunks stay loaded and saved like any world. The selective-save mixins, keep rules and their risks are **gone**. |
| 20 GB limit | whole world + data | **Applies to the mod's own footprint**: jar, sidecar image, static extracts, raw scratch and processed-data cache. The world save grows normally with exploration. |
| Data store | pinned forever (part of the save) | **Evictable cache.** Once a cell's chunks are generated it is no longer needed. Only a tiny manifest of upstream versions is kept forever, to avoid seams on re-fetch. |
| Loot | no containers | **Loot chests in buildings**, using loot tables. They become per-player via **Lootr** (already in the pack). |
| Test area | Bern, Zermatt, Zurich | **Interlaken → Brienz → Meiringen → Innertkirchen → Guttannen → Grimsel Pass** (measured below) |
| Rail | gravel beds | **Vanilla rail blocks** on gravel track beds, with bridges and tunnels. No rail mod. |
| Client | server-only | **Server-only by default**, plus an optional small **client companion mod** if sky or fog render badly at very negative y |
| BlueMap / Chunky | excluded | **Usable again**, because chunks are saved normally. Chunky is optional for admins; nothing is pregenerated by default. |

Unchanged from v2: lazy generation outward from an admin-set origin, data fetched on demand by a `swissdata` sidecar, 1:1 scale, tall dimension, vanilla blocks, auto-furnishment, `/swiss` commands, normal building and mob spawning.

## 0. TL;DR

- **Scale and height:**
  - 1:1 horizontal (1 block = 1 m).
  - One tall dimension, y −2032…2031.
  - Mapping `y = h − 2000` up to 3000 m, then compressed ×0.6 above.
  - Buildings are always at true height.
- **Lazy generation:**
  - Chunks generate when players first load them, outward from an admin-set real-world origin.
  - They are then **saved like any vanilla chunk**.
  - Nothing is pregenerated.
- **Data on demand** from the swisstopo download API (STAC):
  - A small **`swissdata` sidecar container** (Python + GDAL) downloads tiles and turns them into compact 1 km² cells on a volume shared with the server.
  - The mod reads cells straight from disk.
  - Cells are a cache: they can be evicted once their area is generated.
- **Mod footprint ≤ 20 GB:** sidecar image, extracts, scratch and cell cache. The world save is not counted.
- **Buildings:**
  - swissBUILDINGS3D solids, voxelized.
  - Vanilla palettes chosen by building type and age.
  - **Furnished, lit rooms** with **loot chests** (Lootr makes them per-player).
- **Surface:** lakes with real bathymetry, stepped rivers, roads, bridges, tunnels, **vanilla rail tracks**, forests, glaciers.
- **Players:** `/swiss`, `/swiss goto <place>`, `/swiss back`, `/swiss where`. Normal building, mobs spawn.
- **Test area:** Interlaken → Grimsel Pass, ~1,290 km².
  - Lake, small towns, a gorge, forest, alpine pasture, glacier and reservoirs.
  - About **1.4 GB of downloads** in total (measured).

## 3. Vertical mapping (unchanged)

The datapack limits are `min_y -2032`, `height 4064` (y −2032…2031).

```
y(h) = h − 2000                  for h ≤ 3000 m   (1:1)
y(h) = 1000 + (h − 3000) × 0.6   for h > 3000 m
```

| Place (test area in bold) | h | y |
|---|---|---|
| **Brienzersee bed** (≈ 300 m) | ~300 | ~−1700 |
| **Brienzersee / Interlaken** | 564 / ~568 | −1436 / −1432 |
| **Meiringen / Innertkirchen** | ~595 / ~625 | ~−1405 / ~−1375 |
| **Grimsel Pass** | 2164 | 164 |
| **Finsteraarhorn** (just south of the area) | 4274 | 1764 |
| Dufourspitze | 4634 | 1980 |

- **Buildings, bridges, tunnels and tracks** are extruded 1:1 from their mapped base.
- **Snow:**
  - Vanilla's height-adjusted temperature should start at y 80 ≈ 2,080 m, so snow appears from about 2,300 m.
  - The Grimsel Pass sits right at that line, which makes it a good test. Verify in the 1.21.1 source in M1.
- **Sea level:** set explicitly in the dimension's settings (proposal: the lowest lake level in the generated area). Decide together with the temperature check.
- **Spawn side effects of the negative y range:**
  - Slime chunks below y 40 would put slimes everywhere below ~2,040 m.
  - Bats spawn in dark spaces below sea level.
  - Fish and drowned use bands relative to sea level.
  - **Fix:** hand-picked spawn lists per biome. Keep the `swissworld:` biomes out of `#minecraft:is_overworld` and `#c:is_overworld`, so other mods' spawns, features and structures don't leak in.
- **Dimension type** `swissworld:swiss_tall`: `min_y -2032`, `height 4064`, `logical_height 4064`, `effects minecraft:overworld`, `bed_works true`, `has_skylight true`, `natural true`.
- **Sky and fog at very negative y:** see §10a (optional client companion).

## 4. Origin and lazy generation

"Server 0,0" here means **block (0, 0) of the Switzerland dimension**. The overworld is unaffected.

- **Admin sets the real-world origin:**
  - `/swiss admin origin <E> <N>` (LV95), `/swiss admin origin <lat> <lon>` (WGS84), or `/swiss admin origin place <name>` (swissNAMES3D).
  - It can also be set in `swissworld-server.toml`.
  - **Default: Interlaken**, Höhematte (≈ E 2,632,900 / N 1,170,600, to be confirmed in M0).
- **Coordinate transform:** `x = E − E0`, `z = N0 − N`. +z points south. 1 m = 1 block. The origin is rounded to whole metres.
- **Lock:**
  - The origin is stored in the dimension's `SavedData` and **locked once the first chunk is generated**.
  - Changing it afterwards needs `/swiss admin reset confirm`, which wipes the dimension's region files. The cell cache can stay, because it is in LV95.
- **Outward generation:**
  - The player spawn in the dimension is at the origin (0, surface, 0).
  - Chunks generate wherever players go.
  - The sidecar **prefetches data**:
    - a ring around the origin at startup (default 2 km);
    - **ahead of moving players**, along their velocity vector, ~60 s × speed (at least 500 m; ~2 km at elytra speed).
- **Edges:** generation only where data exists (border handling: open question Q1).

### Test area: what it actually costs (measured)

- **Bbox:** WGS84 7.80–8.39 E, 46.56–46.80 N, about LV95 E 2,628–2,672 km, N 1,154–1,181 km.
- **Terrain:** 1,288 swissALTI3D 1 km tiles, about **1.26 GB** of downloads.
- **Buildings:** 110 swissBUILDINGS3D sheets, **168 MB** in total (latest versions: 87 × 2021, 17 × 2024, 5 × 2025, 1 × 2020).
- **Bathymetry:** Brienzersee, Thunersee and Lungernsee.
- **Total ≈ 1.45 GB** of downloads for ~1,290 km².

**Licence:** swisstopo OGD allows free use, including commercial, with **mandatory attribution "©swisstopo"**. It is shown on first entry and on `/swiss info`. The terms say **excessive use may be restricted**, so the sidecar must be polite:

- at most 2–4 concurrent downloads;
- a User-Agent with a contact address;
- each asset downloaded once;
- exponential backoff on errors.

## 6. Architecture

```
                    swisstopo STAC (HTTPS, on demand)
                                │
   ┌────────────────────────────▼──────────────────────────────┐
   │ swissdata sidecar (Docker, Python 3.12 + GDAL, ~1.5 GB img)│
   │  - fetch queue (rate-limited, deduplicated, retries)       │
   │  - raw scratch (transient, cap 2 GB, deleted after use)    │
   │  - processor: 1 km² LV95 cell → cell.swd (zstd)            │
   │      terrain 2 m · surface class 1 m · water levels ·      │
   │      roads/rail/paths (+ bridge/tunnel 3D) ·               │
   │      building column spans + building table (GWR)          │
   │  - writes cells atomically (tmp + rename) to the shared    │
   │    volume; updates manifest.json                           │
   │  - HTTP on the docker network (control plane only):        │
   │      POST /request {cells[]} · POST /prefetch · GET /status│
   └──────────────┬─────────────────────────────┬──────────────┘
         writes   │                             │ requests for misses
   ┌──────────────▼──────────────┐              │
   │ SHARED VOLUME               │              │
   │ cells/*.swd  (cache, LRU)   │              │
   │ manifest.json (kept forever)│              │
   └──────────────┬──────────────┘              │
         reads    │                             │
   ┌──────────────▼─────────────────────────────▼──────────────┐
   │ NeoForge mod "swissworld" (server-side)                     │
   │  CellCache (heap LRU ~256 cells) ← reads .swd from disk     │
   │  SwissChunkGenerator.fillFromNoise → CompletableFuture      │
   │     completes when the needed cells are present             │
   │  SwissBiomeSource · buildings · furnishing · loot · /swiss  │
   │  vanilla chunk saving (unchanged)                           │
   └─────────────────────────────────────────────────────────────┘
   optional: swissworld-client (sky/fog only, §10a)
```

**Why a sidecar:**

- Buildings only come as FileGDB or DWG, and Java can't read FileGDB.
- Keeping GDAL out of the Minecraft JVM avoids native crashes.
- The sidecar can be restarted or updated independently.

**Fallback, if you'd rather not run a second container:**

- The jar fetches ALTI3D COGs itself (pure Java TIFF).
- Buildings come from a one-time extract made on this Mac. That costs roughly 5–10 GB of the budget (unverified), and buildings are only available for the extracted area.

**Cell format `.swd`:** one file per 1 km² LV95 cell, aligned with the swisstopo tiles and independent of the origin. A chunk needs at most 4 cells.

| Layer | Content | Size per km² |
|---|---|---|
| Terrain | uint16 `(h + 200 m) × 10` (dm), 2 m grid, 501×501 with overlap | 0.5 MB raw, ~0.1–0.2 MB compressed |
| Surface class | uint8, 1 m, RLE/zstd | ~20–60 KB |
| Water | water-body id per column, level table, stepped river levels | small |
| Overlays | road/rail/path class, width, deck elevation (bridge), tunnel spans | small |
| Buildings | column spans (y0, y1 in dm, building index, part) plus a building table (EGID, palette, floors, footprint, entrance side) | 0–3 MB in towns |

Target: **≤ 0.5 MB/km² on average** (measured in M0).

**Cell cache and versions:**

- Once every chunk a cell covers has been generated (the mod tracks this per cell), the cell is no longer needed and can be evicted first.
- Partly generated cells are evicted last.
- `manifest.json` permanently records which upstream asset each cell came from (e.g. `swissalti3d_2019_2632-1170`, `swissbuildings3d_3_0_2021_1209-13`, `swisstlm3d_2026-02`). A re-fetch uses **the same version**, so newly generated chunks always line up with already saved neighbours.
- If swisstopo has withdrawn that version, the sidecar fetches the newest one and logs a possible seam.

**Async generation, never blocking the main thread:**

- `fillFromNoise` returns a `CompletableFuture`. If cells are missing, it requests them and completes when they arrive. Chunks simply appear a bit later.
- **Synchronous loads** (teleport, login, respawn) are only a risk in **never-generated** areas, because saved chunks don't need cells:
  - `/swiss goto` and `/swiss` (first entry) **prefetch first, then teleport**: "Fetching data for Grimsel… (3 s)".
  - Admin `/tp` into unknown areas: a command hook prefetches first, or this is documented as a risk.
- **Synchronous queries never wait.** `getBaseHeight` and `getNoiseBiome` for an unloaded, unfetched position return a non-blocking default and trigger a request.
- **Sidecar or swisstopo down:**
  - Already generated areas are unaffected.
  - New areas stay pending.
  - **A placeholder is never generated or saved.**
  - `/swiss admin status` shows the queue and errors.

**Generator versioning (lighter now):**

- Saved chunks never change. A generator update only affects chunks generated later, so it can create a seam at the frontier of explored land.
- `generatorVersion` in SavedData plus a golden-hash test in CI make such changes deliberate rather than accidental.

**Server and client:**

- The core mod is **server-side**: vanilla blocks, datapack biomes and the dimension type are synced as data. A pack client without `swissworld` can join.
- packwiz `side = "server"`.
- The optional client companion (§10a) is `side = "client"`, and nobody is required to install it.

## 8. Buildings, furnishing and loot (vanilla blocks)

### Geometry

- Source: swissBUILDINGS3D 3.0 **Solid**, read from FGDB in the sidecar. For each 1 m column, cast a vertical ray through the closed mesh; the intersection pairs give the inside spans.
- **What the spans give us:** walls (any outside neighbour), roof (nothing inside above), and floor slabs every 3 blocks from the base (aligned to the GWR floor count when it fits).
- **Roofs:** slopes become stairs (with facing) or slabs (spans at 0.5-block resolution).
- **Ground:** the base sits at the solid's lowest point, with terrain under the footprint flattened or stepped.
- Footprint extrusion is only a fallback for buildings without a solid.
- **Cross-chunk structures:** a building is generated per chunk from the shared cell data, so it is complete regardless of which side loads first. The same goes for furniture and trees.

### Vanilla palettes

Chosen from GWR category, class and period plus altitude and region, with a deterministic per-building variant. Palettes are JSON with a fallback order, so Macaw's or other block mods can be added later without a generator rewrite.

| Type | Facade | Roof | Windows / extras |
|---|---|---|---|
| House, lowland, post-1919 | white/light-gray concrete, calcite, smooth quartz | brick / mud brick / granite stairs (red-brown tiles) | glass panes, spruce trapdoor shutters |
| Old town, pre-1919 (Interlaken, Brienz centres) | stone bricks, smooth sandstone | brick / deepslate tile stairs | regular pane rows |
| **Chalet** (Bernese Oberland, any altitude for small wooden residential; Brienz and Meiringen have many) | spruce/dark-oak planks over a stone plinth | deepslate tile / dark-oak stairs, wide overhangs | spruce trapdoor shutters, balconies of fences |
| Barn / agricultural / alpine hut | spruce/oak planks, stripped logs | deepslate tiles, gray concrete (Eternit) | none |
| Hotel (Interlaken Höheweg, Grimsel Hospiz) | calcite, smooth quartz, stone plinth | deepslate tile, copper accents | many windows, balconies |
| Industrial / power station (KWO Innertkirchen, Grimsel) | gray/light-gray concrete | flat gray concrete | glass bands |
| Commercial / offices | light-gray concrete + glass | flat; moss for green roofs | full-height glass |
| Church | stone bricks, calcite | deepslate tiles, copper spire | stained glass |

**Dams** (Grimsel, Räterichsboden, Spitallamm) are not in swissBUILDINGS3D. They come from TLM3D (`Staumauer`) and are built from concrete blocks up to the reservoir level.

### Auto-furnishment (simple, deterministic)

**Layout per building:**

1. Floors come from the slabs.
2. A **stair core** (stair run with landings) goes next to the **entrance**, which faces the nearest road or path.
3. Each floor is BSP-split into rooms of about 3–8 m, with plaster interior walls and door gaps.
4. Each room gets a type from the building type and floor.

| Room | Furniture |
|---|---|
| Living | stair sofa + trapdoor sides, carpet, slab/trapdoor table, bookshelves, flower pots |
| Kitchen | smoker/furnace, cauldron sink, crafting table, smooth-stone counter, stair chairs |
| Bedroom | bed (colour per building), barrel wardrobe, carpet |
| Bathroom | cauldron, quartz, white carpet |
| Office / shop | stair chairs, slab desks, lecterns, barrels as shelves |
| Hotel room | bed, small table, carpet; reception desk on the ground floor |
| Workshop / industrial | anvil, grindstone, blast furnace, chains |
| Church | stair pews, quartz altar, candles |
| Barn / alpine hut | hay bales, composters, fence stalls |

**Rules:**

- **Every room gets at least one light source** (hanging lantern, or covered glowstone in the ceiling), so houses don't turn into mob spawners.
- **No entities** in worldgen (no paintings, item frames or armor stands); they'd need entity serialisation for little gain.
- Rooms smaller than 4×4 m get only a light. Huge halls get lights plus sparse props.

### Loot chests (new)

- **Placement:**
  - Chests or barrels with a **loot table reference**, not pre-filled items. Contents roll when first opened.
  - Placed deterministically by room type (kitchen cupboard, bedroom wardrobe, office cabinet, workshop toolbox, cellar), up to a configurable density.
  - Proposal: ~1 per residential unit, 2–4 per shop or workshop, a few in hotels and the power station, rare in barns and huts.
- **Per-player loot via Lootr:**
  - Lootr 1.11.38 is in the pack (`side = both`).
  - Option 1: place vanilla containers with a `LootTable` tag and let Lootr convert them.
  - Option 2: place `lootr:lootr_chest`/`lootr_barrel` directly. The palette falls back to vanilla chests if Lootr is absent.
  - **Which one works for chunks from a custom generator is verified in M3.** Either way, every player gets their own roll and no chest is looted out for everyone.
- **Loot tables:**
  - One table per room type: `swissworld:chests/{residential_kitchen, residential_bedroom, cellar, shop, office, workshop, hotel, power_station, alpine_hut, barn}`.
  - Contents are **mixed automatically from what the server has** (§13.2): pools are built at datapack reload from all loaded chest tables and item tags, with a denylist.
  - A datapack or KubeJS override of a table wins over the automatic one.
- **Rare finds:** a small configurable chance of a "safe" (iron-trimmed barrel, better table) in banks, post offices and the power station.

### Block mods

Deferred. Recommended later: Macaw's Roofs + Windows + Doors (v1 evaluation).

## 9. Surface

- **Lakes:**
  - A water level per TLM polygon (Brienzersee 564, Thunersee 558, Grimselsee ~1,909, Räterichsbodensee ~1,767, Totensee ~2,160; levels confirmed from TLM in M0).
  - Depth from swissBATHY3D where available, otherwise synthetic.
- **Rivers:**
  - The water surface is monotonic downstream and stepped: flat runs of source blocks, 1-block drops, waterfalls.
  - Test cases: the Aare through Interlaken, the **Aareschlucht** gorge (narrow, deep), the **Giessbach falls** and the **Handegg** falls.
- **Roads:**
  - Width from TLM `OBJEKTART`.
  - Main roads in concrete, smaller roads in andesite, paths as dirt path/gravel.
  - Hairpins on the Grimsel road are a good test.
  - **Bridges and tunnels** use `KUNSTBAUTE` plus the 3D Z values.
- **Rail (vanilla blocks, no rail mod):**
  - TLM railway lines become a **gravel or andesite track bed** with **vanilla rails** on top: straight runs, curves, and ascending rails where the slope allows.
  - Diagonal lines are drawn as a staircase of straight segments, which vanilla handles as zig-zag.
  - Viaducts and tunnels are built.
  - Test: the **Brünig line** (Interlaken Ost–Brienz–Meiringen) and the **Meiringen–Innertkirchen** line. The Brünig rack section on the pass itself is steeper than vanilla rails can go and only gets a track bed there.
  - Regular rails are craftable from iron, so players can mine them. That's normal survival behaviour and costs nothing here.
  - Powered rails: none by default (gold); configurable.
- **Land cover:**
  - glacier (snow/packed ice/blue ice, 3–8 blocks; e.g. Unteraargletscher, if inside the final bbox);
  - rock and scree;
  - forest (species by altitude band and region; trees computed per chunk);
  - meadows and alpine pastures;
  - urban paving.
- **Biomes** (`swissworld:`): `urban`, `colline`, `colline_forest`, `montane_forest`, `subalpine_forest`, `alpine_meadow`, `rock`, `scree`, `glacier`, `lake`, `river`. Each has its own spawn list.

## 10. Players and the pack

**Commands:**

| Command | Who | What |
|---|---|---|
| `/swiss` | all | Enter at the origin (or the last position), or leave if already inside. Prefetches before teleporting. |
| `/swiss goto <place>` | all | swissNAMES3D place (accent-insensitive, `Genf`/`Biel` work), tab-completed. Best match wins: settlements first, bigger first; "also:" lists up to 3 clickable alternatives. Prefetch, then teleport to the surface. |
| `/swiss goto <a> <b>` | all | Real coordinates: LV95 (`2638359 1237558`), LV03 (`638359 237558`) or WGS84 lat lon (`47.2878 7.9457`). Waits for the terrain, lands on the ground. |
| `/swiss back` | all | Return to the saved overworld position |
| `/swiss where` | all | LV95 + WGS84 coordinates, real altitude, a map.geo.admin.ch link |
| `/swiss info` | all | Attribution ©swisstopo, data versions |
| `/swiss admin origin …` / `reset confirm` | op | Show or set the origin (`<E> <N>`, or `place <name>`), only while not locked; wipe the dimension |
| `/swiss admin status` / `prefetch <area>` / `evict` | op | Queue, cache and footprint vs. the 20 GB budget, region-file size, errors |

**Gameplay and pack interaction:**

- **Building:** normal, no protection.
- **Mobs:** natural spawning per biome list; houses are lit.
- **Hordes:** `waves.js` already skips non-overworld dimensions. The Hordes and Undead Nights may run here; M2 checks whether they need a dimension whitelist entry (§13.3).
- **BlueMap:** works again. Add a map for the dimension and limit its rendered height range, otherwise the tall dimension renders a lot of air. Test the render cost in M4.
- **Chunky:** optional, for an admin who wants to pregenerate e.g. the Interlaken bowl ahead of an event. Generation waits on data, so prefetch the area first.
- **Xaero's maps:** client-side, should work; verify the tall dimension in M1.
- **Tough as Nails:** check its temperature at very negative y and in custom biomes (M2).
- **Lootr:** see §8.

### 10a. Optional client companion `swissworld-client`

Only built if the M1 sky test shows problems. Vanilla ties some sky and fog behaviour to absolute height, and almost all of the test area is at y −1440…+200. Possible symptoms:

- a darkened sky or horizon when the camera is far below sea level;
- void fog;
- clouds at y 192 that appear far above the valleys.

The companion would contain only a `DimensionSpecialEffects` for `swissworld:switzerland` and a few targeted mixins:

- horizon/darkness relative to the mapped sea level;
- cloud height relative to terrain.

It is purely cosmetic and **not required to join**. Players without it just see vanilla sky behaviour. Check compatibility with Iris shaders in M1.

## 12. Risks

| Risk | Mitigation |
|---|---|
| Main-thread synchronous load waits on the network → watchdog | Only possible in never-generated areas: prefetch-then-teleport, `/tp` hook, non-blocking defaults for height/biome queries |
| swisstopo throttles us, or the API or asset names change | Rate limiting, caching, versions in the manifest; generated areas stay playable regardless |
| Re-fetched data is a different version → seam next to saved chunks | Manifest pins the exact upstream item; a seam is only possible if swisstopo withdraws it (logged) |
| Generator update changes output → seam at the exploration frontier | `generatorVersion`, golden-hash CI test, deliberate bumps |
| World save grows large with heavy exploration | Not in the 20 GB budget by your decision; reported in `/swiss admin status`; can be trimmed with standard tools (e.g. deleting rarely visited regions) |
| Lootr doesn't convert containers placed by a custom generator | Place Lootr blocks directly (palette fallback to vanilla); verified in M3 |
| Loot balance clashes with server economy | Data-driven tables, KubeJS override, density config |
| Tall dimension cost (lighting, client memory, BlueMap render) | Measure in M1/M4; BlueMap height limits |
| Sky/fog wrong at very negative y | Optional client companion (§10a); or shift the mapping up |
| swissBUILDINGS3D is beta (the schema may change) | Semantics from GWR; pinned versions |
| A sidecar adds operational complexity | Single compose service with health check; generated areas don't depend on it; fallback design without it (§6) |

## 13. Decisions (round 4) and remaining questions

1. **Border → ocean.**
   - `coverage.bin` (from swissBOUNDARIES3D, built once) marks every km cell as outside, border or inside. Border cells carry a per-column `INSD` mask.
   - Outside Switzerland, the generator fills a flat **ocean** with its surface at 193 m (the lowest point of Switzerland, y −1807). That is also the dimension's sea level. The sea floor sits ~30 blocks below, with a sand/gravel shelf sloping down from the border.
   - Where the border cuts through a lake that sits higher (Léman 372 m, Bodensee 395 m, Lugano 271 m), the lake keeps its own level and a **solid rim** (stone cliff down to the ocean) closes it off. Generated water is placed as source blocks with no pending fluid ticks, so nothing drains.
   - M2 tests: a border column next to ocean is watertight, and a cut lake does not leak.
2. **Loot: mixed automatically from what the server has.**
   - On datapack reload, `swissworld` builds its room-type pools from two sources:
     - (a) the entries of every loaded `*:chests/*` loot table from all namespaces (vanilla, mods, KubeJS);
     - (b) tag-based pools (`c:foods`, `c:ingots`, `c:tools`, `c:armors`, …).
   - Items are weighted by rarity and capped per chest.
   - A **denylist** removes spawn eggs, command/structure/jigsaw/debug/barrier/light blocks, creative-only and `minecraft:*_spawn_egg`-style items. It is configurable.
   - Modded items (e.g. superb-warfare) therefore appear **only if they are already in some chest table or tag**.
   - `/swiss admin loot preview <roomType> <n>` rolls n chests into chat for balancing.
3. **Hordes:** allowed to run. M2 checks whether The Hordes / Undead Nights need a dimension whitelist entry and documents it. `waves.js` stays overworld-only unless the user changes it.
4. **Sidecar:** approved (`swissdata` container sharing the store volume).
5. **Still open (needed only at M4):** which host path holds the store volume (≤ 20 GB) and the growing world save.

**Rules for every agent:**

- Change contract files (`docs/*.md`, `swd.py`, `SwdReader`, fixture) only in agreement with the coordinator. Format changes are one commit across both sides.

- Never the production server. The pack is read-only.
- Downloads go to the shared `.data-cache/raw/`.
  - Only `sidecar-tlm` downloads the whole-country TLM.
  - Nobody downloads `swissbuildings3d_3_0_20xx` country items (14 GB).
